# Thai Natural Language & Tone Guidelines (การสื่อสารภาษาไทยอย่างเป็นธรรมชาติ)

ทักษะนี้เป็นคู่มือแนะนำให้ AI เลือกใช้ระดับภาษา (Tone & Register), คำศัพท์ (Terminology) และโครงสร้างประโยคภาษาไทยให้สอดคล้องกับบริบทของงาน เพื่อหลีกเลี่ยงภาษาแปลก ๆ (AI-slop / สำนวนแปลตรงตัวจากภาษาอังกฤษ) และทำให้เนื้อหาเป็นธรรมชาติ กระชับ ชัดเจน

---

## 1. การเลือกระดับภาษาตามบริบทงาน (Register & Tone Mapping)

| บริบทงาน (Context) | ระดับภาษา (Register) | ตัวอย่างการใช้คำ | สิ่งที่ควรหลีกเลี่ยง |
| :--- | :--- | :--- | :--- |
| **การเขียนโค้ด / Tech / Engineering** | กึ่งทางการ, มืออาชีพ, ตรงไปตรงมา, ทับศัพท์ที่นิยม | "กำลังรันคำสั่งทดสอบ", "แก้ไขบักการเชื่อมต่อ", "ส่ง PR", "ปรับแต่ง query" | แปลคำศัพท์เฉพาะทางจนอ่านไม่รู้เรื่อง เช่น "ดึงคำขอ", "ตัวผลักดัน" |
| **ข้อความ UI / UX (Microcopy)** | กระชับ, ชัดเจน, คำสั้น, เป็นมิตร | "บันทึกโน้ต", "ลบรายการ", "คัดลอกสำเร็จ", "ไม่พบข้อมูล" | ประโยคเยิ่นเย้อ เช่น "การดำเนินการเสร็จสิ้นเรียบร้อยแล้ว" |
| **เอกสารทางการ / สรุปผู้บริหาร (Docs/Executive)** | ทางการ, สุภาพ, สละสลวย, เชิงโครงสร้าง | "สรุปภาพรวมระบบ", "ผลกระทบและความเสี่ยง", "แนวทางแก้ไขปัญหา" | ภาษาพูดเกินไป เช่น "เรื่องนี้ค่อนข้างพัง", "ติดปัญหาเยอะมาก" |
| **การอธิบาย / สอน / แนะนำผู้ใช้ (Consulting/Chat)** | สุภาพ, เข้าใจง่าย, เป็นกันเองแต่ให้เกียรติ | "ขอแนะนำให้ปรับแบบนี้ครับ", "สามารถทำได้ตาม 3 ขั้นตอนนี้ครับ" | ประโยคหุ่นยนต์ ท่องจำ หรือคำลงท้ายซ้ำซากทุกบรรทัด |

## 2. กฎการแปลและทับศัพท์ (Terminology & Loan Words)

### ก. คำที่ควรทับศัพท์ (Industry Standard English)
ในงานสาย Developer / Tech ห้ามฝืนแปลไทยหากศัพท์อังกฤษเป็นสากลและเข้าใจง่ายกว่า:
- **ใช้ทับศัพท์หรือคงรูปอังกฤษ**:
  - `Bug`, `Refactor`, `Commit`, `Push`, `Branch`, `Merge`, `PR / Pull Request`
  - `Database`, `Schema`, `Query`, `Endpoint`, `API`, `Token`
  - `Markdown`, `Live Preview`, `Component`, `State`, `Prop`, `Hook`

### ข. คำศัพท์เฉพาะของโปรเจกต์นี้ (Project Domain Terminology)
อ้างอิงตาม [CONTEXT.md](file:///Users/chitsanuphong/Documents/dataAipredict/note.md/CONTEXT.md) ของโปรเจกต์เสมอ:
- **โน้ต** (ไม่ใช่: ไฟล์ / เอกสาร)
- **Live Preview** (ไม่ใช่: หน้าจอปกติ / โหมดดูตัวอย่างทั่วไป)
- **ต้นฉบับ Markdown** (ไม่ใช่: โน้ต Markdown / ไฟล์ raw)
- **บล็อก** (ก้อนเนื้อหา เช่น ย่อหน้า ตาราง โค้ด)
- **ข้อมูลกำกับโน้ต** (Metadata ส่วนต้น เช่น frontmatter / สีกำกับ)

## 3. การตัดสำนวนแปลภาษาอังกฤษ (Eliminate Translationese)

AI มักติดการแปลไวยากรณ์ภาษาอังกฤษมาเป็นภาษาไทยตรง ๆ ซึ่งทำให้ประโยคแข็งและไม่เป็นธรรมชาติ:

| สำนวนแปลตรงตัว (ห้ามใช้ ❌) | ภาษาไทยที่เป็นธรรมชาติ (แนะนำ ✅) | เหตุผล |
| :--- | :--- | :--- |
| "มันเป็นเรื่องสำคัญที่จะต้อง..." | "จำเป็นต้อง..." / "ควร..." | ภาษาไทยไม่ขึ้นต้นด้วย "มันเป็น..." (It is important to...) |
| "สิ่งนี้ถูกสร้างขึ้นโดย..." | "ฟังก์ชันนี้สร้างโดย..." | เลี่ยงการใช้รูปถูกกระทำ (Passive voice) ในเชิงบวก |
| "ในการที่จะทำสิ่งนี้..." | "หากต้องการทำสิ่งนี้..." / "เมื่อต้องการ..." | ตัดคำเยิ่นเย้อ (In order to...) |
| "สร้างความมั่นใจว่า..." | "ตรวจสอบให้แน่ใจว่า..." / "ตรวจเช็กว่า..." | แปลตรงตัวจาก "Make sure that..." |
| "ดำเนินการทำการตรวจสอบ" | "ตรวจสอบ" | เลี่ยงคำฟุ่มเฟือยซ้อนกัน เช่น "ทำการ...", "ดำเนินการ..." |
| "ในแง่ของประสิทธิภาพ" | "ด้านประสิทธิภาพ" / "เรื่องประสิทธิภาพ" | ตัดสำนวน "In terms of..." |

## 4. โครงสร้างประโยคและการเว้นวรรคภาษาไทย

1. **การเว้นวรรค (Spacing)**:
   - เว้นวรรคหน้าและหลังคำภาษาอังกฤษ ตัวเลข และโค้ด เช่น `ฟังก์ชัน getNote() ทำงานสำเร็จ` (ไม่ติดกันเป็น `ฟังก์ชันgetNote()ทำงาน`)
   - เว้นวรรคแยกประโยคหรืออนุประโยค เพื่อให้อ่านง่าย เพราะภาษาไทยไม่มีการใช้ dot จบประโยค
2. **การใช้คำสรรพนามและหางเสียง**:
   - ในการตอบแชต: ใช้ "ผม" หรือแทนตัวในบริบททีมอย่างสุภาพ มีหางเสียง "ครับ" อย่างเป็นธรรมชาติ ไม่ต้องใส่ท้ายทุกคำ
   - ในเอกสาร / README / คู่มือ: ตัดคำลงท้ายออก ("ครับ/ค่ะ") ใช้ภาษาเขียนที่เป็นกลาง
3. **การบอกขั้นตอน (Step-by-Step)**:
   - ใช้กริยานำหน้า เช่น "1. ติดตั้งแพ็กเกจ", "2. กำหนดค่าคอนฟิก", "3. ทดสอบการทำงาน"
   - กระชับ ตรงประเด็น ไม่อารัมภบทยาวเกินความจำเป็น
